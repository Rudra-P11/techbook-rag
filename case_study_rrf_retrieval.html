2. Mathematical Mechanics: Reciprocal Rank Fusion (k = 60)

Standard dense vector search generates unbounded cosine similarity scores in range [0, 1], while BM25 Okapi generates unbounded frequency scores in range [0, ∞). Naively combining these with raw weights requires delicate calibration that breaks across diverse queries.

Reciprocal Rank Fusion (RRF) resolves this problem by discarding raw score magnitudes and operating purely over ordinal rankings:

RRF Score(d) = ∑ [ 1 / (k + Rank_m(d)) ]
Where k = 60 (standard Cormack et al. constant) and m ∈ { Dense ANN, BM25 Lexical }

With k = 60, the highest possible contribution from a single retrieval engine is 1 / (60 + 1) = 0.016393. When a candidate performs well in both stages, its reciprocal sum compounds, prioritizing it over candidates that only ranked high in a single model.

6. Architecture Takeaways for Production Systems

This empirical case demonstrates three core principles of production RAG design:

  1. Dense models suffer from keyword blindness: Dense vector spaces can fail when a specific query relies on exact terminology ("forward pass"). Chunk #4 scored highest in term frequency but was 20th in dense similarity.
  2. BM25 lacks semantic conceptualization: BM25 alone struggled to recognize that the loop X = layer.forward(X) (Chunk #5) is the core canonical forward pass, ranking it down at 15th. Dense search recognized its semantic relevance (6th).
  3. RRF eliminates score normalization vulnerabilities: Because reciprocal rank fusion does not require min-max scaling or z-score normalization across disjoint score distributions, it remains robust across all queries and domain shifts.
