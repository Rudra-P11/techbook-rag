01 Why These Architectural Choices?

Building production RAG over dense technical literature requires deliberate trade-offs across chunking granularity, vector dimensions, memory footprint, and retrieval fusion.

Decision 1 • Vectorization & Embeddings
Why did we choose BAAI/bge-small-en-v1.5 instead of larger alternatives?

We chose BAAI/bge-small-en-v1.5 to satisfy our 2–5s SLA on commodity hardware without requiring expensive NVIDIA CUDA GPUs or burning paid API tokens per search query:

Model Parameters Dimensions CPU Inference RAM / Storage Footprint Fit for This Project
BAAI/bge-small-en-v1.5 33.3M 384 15 – 25 ms ~150 MB RAM (1.5 KB / vector) Optimal (Chosen)
BAAI/bge-large-en-v1.5 335M 1,024 180 – 350 ms ~1.4 GB RAM (4.1 KB / vector) Too slow on CPU
OpenAI text-embedding-3-small API hosted 1,536 120 – 250 ms (Network) Paid API cost per query Violates offline OSS rule

Vector Storage Economics: 384 dimensions require 4x less memory in Qdrant HNSW graphs than 1536-dimensional OpenAI embeddings, allowing the entire 2,810-chunk index to execute inside sub-millisecond RAM caches.

Decision 2 • Chunking Architecture
Why 700 tokens with 15% overlap?

Chunking technical books requires solving the Context Truncation Dilemma:

  • If chunks are too small (200–300 tokens): Multi-line SQL CTE queries, recursive Python functions, and mathematical proofs are cut in half, destroying syntactic integrity.
  • If chunks are too large (1,500+ tokens): Embeddings suffer from semantic dilution, making specific concepts harder to isolate in ANN vector space.
  • The 700-token sweet spot: Perfectly captures 2 to 3 cohesive textbook paragraphs or a complete code block alongside its explanatory commentary.

15% Overlap (105 tokens): Implemented via token-aware sentence boundary snapping. If an essential algorithmic definition lands across a chunk break, it is guaranteed to appear in full in both adjacent chunks.

Decision 3 • Hybrid Search & RRF Fusion
Why Reciprocal Rank Fusion (k=60) instead of Weighted Sum?

Dense embeddings produce cosine similarity scores bounded in $[0, 1]$, whereas BM25 Okapi produces unbounded frequency scores in $[0, \infty)$. Linear weighted sum ($\alpha \cdot \text{Dense} + (1-\alpha) \cdot \text{BM25}$) fails because score scales shift wildly between short and long queries.

RRF eliminates score normalization vulnerabilities: It operates strictly over ordinal positions: $\text{RRF}(d) = \sum \frac{1}{60 + \text{Rank}_m(d)}$. As proven in our empirical case study, this allows BM25 to rescue exact terminology matches (like Chunk #4, promoted +16 ranks into the context window) while preventing single-keyword spam from overwhelming semantic relevance.

In a neural network, a forward pass is the initial computational phase where input data flows sequentially through the network's layers to compute activations and produce predictions [Deep Learning from Scratch, pp. 176-177].

for layer in self.layers: X = layer.forward(X) return X

During this pass, each layer computes affine transformations followed by nonlinear activations. This is explicitly contrasted with the backward pass, where loss gradients are propagated in the reverse direction using the chain rule [Deep Learning from Scratch, pp. 86-87, 178-179].
